## Reporting a vulnerability

Report security vulnerabilities privately to the e-mail address in the **Contact** section below
with the subject **"SECURITY"**. Please include:

- the app version and platform (iOS / Android);
- your device model and operating system version;
- the impact of the vulnerability and the steps to reproduce it.

Do not disclose the vulnerability publicly until a fix has been released.

## Scope

- the Hoppala app for iOS and Android;
- the content and game server the app uses.

While testing, do not run anything that slows down or stops the service (load testing, denial of
service), and do not access, modify or delete other players' data. If you accessed more data than
needed to confirm a vulnerability, say so in your report.

## How reports are handled

- We reply to reports within 7 days.
- We aim to release a fix within 90 days and coordinate disclosure with you (90-day responsible
  disclosure).
- Server-side fixes are applied immediately; app fixes are released through the App Store and
  Google Play (with expedited review where possible).

## Supported versions

Security fixes are released only for the latest version published on the App Store and Google
Play.

## Security model

- Hoppala has no accounts or passwords; the app never asks for a name, e-mail address or phone
  number.
- All connections between the app and the server are encrypted with HTTPS. Content requests carry
  no credentials or cookies.
- When answer analytics or Challenge is used, the server generates a random installation ID and an
  expiring access token. The token is kept in the device's secure storage (iOS Keychain,
  Android Keystore-backed storage).
- In versions where Challenge is enabled, nicknames are generated by the server; players cannot
  enter free text. Scores are verified on the server.

Which data is processed is described in the [Privacy Policy](/en/projects/hoppala/privacy/).
